## 主題簡述

評估並決定是否將專案中所有與指令列相關之命名統一由 `cmd` 重命名為 `cli`（例如 `cmd_tool` → `cli_tool`、`cmd_bar` → `cli_bar`、`cmd_executor` → `cli_executor` 及相關文件與變數參照）。

**本計畫的約束**

- 嚴格遵循 Allman 大括號風格、全小寫 snake_case 命名與結尾分號 `;`。
- 遵循三層單向架構。
- 拒絕隱性補齊。

## 規劃描述

1. **評估命名語意與範疇**：
   - `cmd` 通常偏向單一指令（Command），而目前系統中的指令輸入列與除錯終端實質上為完整的命令列介面（Command Line Interface, CLI）。
   - 評估重命名之影響範圍：包括 `packs/cmd_tool`、`packs/basic_ui/cmd_bar.ts`、`cmd_executor.ts`、CSS 前綴（如 `.basic_ui_cmd_*`）及文檔規則。
2. **決斷與執行遷移**：
   - 經使用者決斷確認後，若決定更名，則批次進行目錄、檔案、變數、CSS 與文檔參照之重構遷移。

## 觀察與推論

### O1 · 2026-08-22 15:29:00+08:00 — cmd 與 cli 命名語意定位
目前專案中將命令列面板與字串解析模組命名為 `cmd_bar` 與 `cmd_tool`。隨其定位明確轉型為除錯控制台與命令列介面（CLI），評估統一重命名為 `cli` 是否更能精確反映其模組職責。
