Design size limits for basic_ui panel resize in the cleanroom redesign

Open design, not decided. Candidate from discussion 2026-10-16: express min_width, max_width, min_height, max_height as CSS length strings (e.g. 'calc(100vw - 32px)', 'calc(10% + 2px)'), set them as the element's CSS min/max, and let the browser clamp; drag only sets width/height and writes back offsetWidth/offsetHeight to avoid a dead zone. This removes the JS clamp and the window size - 32 fallback.

Open questions: whether downstream code needs the limits as px numbers (percent limits are not resolved by getComputedStyle, so a measuring helper would be needed); whether splitter minimums follow the same model.
