# docket

記錄工作與決策；工具檢查一致性，完成與否決只由人判定。

## 概念

- **計畫**：一個主題一份檔案；含主題簡述（存在原因與約束）、觀察、格子。
  生命週期為進行中、已完成、已關閉（被取代或放棄）。
- **觀察**：帶時間的事實或推論。
- **格子**：一件待辦，有正文（現況）與沿革（變化），並可記錄依據（觀察）、依賴與移交（其他格子）。
  狀態分為開放與終態（完成、否決、移交）。
- **索引**：由所有計畫推導出的總覽。

計畫有全域序號，觀察與格子在計畫內編號，格子以兩者合成全域位址。

## 不變式

1. 編號唯一、不重用；檔案內的識別與檔名一致。
2. 觀察與沿革只追加；矛盾的觀察以較晚者為準。
3. 格子不刪除，以終態結束；agent 最多推進到等待確認。
4. 關係只單向記錄，反向由推導取得；依賴無環；移交不指向自己。
5. 已完成的計畫，格子全為終態；已關閉的計畫須有捨棄原因；被取代的計畫須有後繼。
6. 所有引用都能解析。

## 推導值

阻塞、承接、進度、焦點：只計算，不儲存。

## 檢查

- 檢查所有可由當下檔案判定的規則；其餘靠審閱。
- 違反為衝突（失敗），結構異味為警示（不失敗）。
- 只回報，不修復；無法解析即衝突。

## 架構

一個 parser library 定義如何讀取計畫；兩個介面只依賴它，彼此不依賴：

- **索引產生器**：寫入或只檢查；可由編輯事件觸發。索引是計畫的純函式。
- **單格查詢**：唯讀，取一格及其最少上下文，或列出開放格。
