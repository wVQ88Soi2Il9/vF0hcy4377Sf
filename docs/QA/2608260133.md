### A1 · 2026-08-26 01:06 (agent: gemini-3.7-flash-medium)
`execute_command` was failing due to three primary issues:
1. **Type signature mismatch**: The CLI tokenizer produced raw strings, while Core commands (e.g., `create_device_command`) required constructor classes `device_constructor`, string IDs, and numeric arrays `vector`. Passing raw strings resulted in `TypeError: new device_class is not a constructor`.
2. **Missing identifier-to-class resolution layer**: String IDs (e.g., `vanilla:conveyor`) were not resolved into constructors and validated coordinates in an adapter layer.
3. **History commands (undo/redo/jump) not registered in Core Registry**: History operations existed only in `runtime.ts` without public command endpoints.

The legacy `--"<arg>"` syntax mixed flag syntax with positional parameters, adding unnecessary typing friction.

### Q2 · 2026-08-26 01:09 (human: wVQ88Soi2Il9)
Why not use `;` as a delimiter? What other paradigms exist besides space?

### A2 · 2026-08-26 01:09 (agent: gemini-3.7-flash-medium)
1. **Why `;` is discouraged as an argument delimiter**:
   - **Keyboard ergonomics**: The spacebar is the largest key, optimal for touch-typing. `;` resides under the right pinky, increasing fatigue when repeated.
   - **Command chaining**: Across shells and programming languages, `;` is the standard statement separator for chaining multiple commands (e.g. `create conveyor 0 0; move 1 2 2`). Reserving `;` for command chaining enables multi-command one-liners.
2. **Alternative command syntax paradigms**:
   - Preposition DSL (`create conveyor at 4 4 0`)
   - Function REPL (`create("conveyor", [4, 4, 0])`)
   - Key-value pairs (`create id=conveyor pos=4,4,0`)
   - POSIX flags (`create conveyor -p 4 4 0`)
   - Pure positional arguments (`create conveyor 4 4 0`)

### Q3 · 2026-08-26 01:29 ~ 01:31 (human: wVQ88Soi2Il9)
Under a pure positional (Minecraft/Redis) style, should continuous numbers really use space? From a maintainer perspective, continuous numbers have clear advantages:
1. Dimension is fixed.
2. Every cell is a number, easily parsed into a vector.

### A3 · 2026-08-26 01:31 (agent: gemini-3.7-flash-medium)
Comparing comma-aggregated (`4,4,0`) vs space-separated numbers (`4 4 0`):

1. **Comma-aggregated format (`create conveyor 4,4,0`)**:
   - **Pros**: Constant token count (`tokens[2]` is always coordinates), independent of dimension or runtime state; clear boundary.
   - **Cons**: Requires typing commas; needs a secondary `.split(',')` pass.

2. **Space-separated numbers format (`create conveyor 4 4 0`)**:
   - **Pros**:
     - **No secondary string splitting**: Tokenizer produces atomic tokens directly, converted via `args.slice(1).map(Number)`.
     - **Trailing vector regularity**: All coordinate-bearing commands (`create`, `move`) place vectors at the end, matching map dimension.
     - **Strict dimension validation**: Comparing `tokens.length === dim` prevents silent dimension padding.
   - **Cons**: Requires checking token count against active map dimension at the execution layer.
