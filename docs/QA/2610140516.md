### 1. 目錄與檔案

```text
docs/history/                 # P4 起的根目錄
├── ledger.toml               # 設定：紀錄語言、時區
├── head.md                   # 自動產生，嚴禁手改
└── <YYYYMMDDHHMM>_<slug>.md  # 一個主題（thread）一個檔
```

- 檔名就是 thread id，不需要序號。同一分鐘、同一 slug 的重複由檢查器報出。
- 封存：換規格版本時，整批搬到 `archive/`，工具不讀。P4 時 v4 的檔案與 `docs/QA/` 一併封存。
- **所有檔案只能由 CLI 寫入**，人與 agent 都不手改（見第 7 節 `NOT_CANONICAL`）。

### 2. 四種實體

| 實體 | 可變性 | 存的狀態 | 算出的狀態 |
|---|---|---|---|
| **Q 問題** | 只能追加補充 | `dropped`（需 source） | `answered`：有 accepted 的 D 回答它；否則 `open` |
| **D 決定** | 不可變；要改就寫新的 D 取代 | `proposed` / `accepted` / `rejected`（後兩者需 source） | `superseded`：有 accepted 的 D 取代它 |
| **O 觀察** | 不可變 | — | — |
| **T 任務** | 正文可重寫，沿革只追加 | `todo` / `landed` / `accepted` / `rejected` / `handed-off` | `blocked`：`needs` 中有未到終態者 |

- **thread 本身不存 status**：有任何非終態實體就是進行中，否則結束。
- 原本的 `superseded` / `abandoned` 改由 D 表達：哪個決定取代或放棄了哪個方向。
- 「不可變」由 CLI 保證：沒有任何指令能改寫 D、O 的內文。

### 3. 位址

```text
<thread>#<n>           例：202610140516_ledger-spec#3
```

- 一個 thread 內所有實體共用一個流水號，從 1 開始，不重用，由 CLI 分配。
- 類型寫在條目標題裡，不在位址裡。
- 同一 thread 內也寫全位址；工具會檢查每一個引用。

### 4. 檔案文法

````markdown
# 202610140516_ledger-spec

- **prev:** `202610010900_old-topic` 或 —
- **spec:** ledger v1

## 主題

為什麼有這個主題，以及綁住所有實體的約束（≤ 20 行）。

## 條目

### 1 · Q · 2026-10-14 05:16:35+08:00 — 位址要不要用序號

內文。

### 2 · D · 2026-10-14 05:20:00+08:00 — 位址改用時間戳加 slug

- **state:** accepted
- **answers:** 202610140516_ledger-spec#1
- **source:** human: wVQ88Soi2Il9 · 「都照你的建議」

決定內容與理由。

### 3 · O · 2026-10-14 05:30:00+08:00 — 61 份舊計畫從未使用「待決斷」

事實，然後推論。

### 4 · T · 2026-10-14 05:40:00+08:00 — 實作 check 指令

- **state:** landed
- **basis:** 202610140516_ledger-spec#2、202610140516_ledger-spec#3

正文：現在的完整內容。

**沿革**

- 2026-10-14 06:10 landed —— check 完成 → 202610140516_ledger-spec#3
````

- 條目標題固定為 `### <n> · <類型> · <時間戳> — <標題>`，同一 thread 內由舊到新排列。
- 欄位一律寫成 `- **key:** value`，沒有值就省略（例如 T 沒有依賴時不寫 `needs`）；只有 T 有 `**沿革**`。
- 要更正 O，就寫一條新的 O；要改變決定，就寫一個 `supersedes` 舊 D 的新 D。

### 5. 權限矩陣

所有寫入都經過 CLI。

| 轉移 | agent 可直接執行 | 需要 `--source` |
|---|---|---|
| 建立 Q、O、T；建立 `proposed` 的 D | ✓ | |
| T：`todo` → `landed` | ✓ | |
| T：→ `accepted` / `rejected`；D：→ `accepted` / `rejected`；Q：→ `dropped` | | ✓ |
| T：→ `handed-off` | ✓（需指名目標） | |
| 拆分或合併 T | 提議 | ✓ |

`source` 的格式為：`human: <名字> · 「<原話>」`。

CLI 沒有 `--source` 就拒絕這幾個轉移，並檢查格式；無法驗證原話是不是真的。真實性屬於使用者能自行約束的範圍。時間不記在 `source` 裡：條目與沿革由 CLI 蓋時間戳，其餘看 git。

### 6. 只存一個方向的關係

| 存的 | 算出的 |
|---|---|
| `T.needs → T` | `blocks`、`blocked` |
| `T.basis → O/D` | 某個 O/D 被哪些 T 依賴 |
| `D.answers → Q` | Q 是否已 `answered` |
| `D.supersedes → D` | 舊 D 是否已 `superseded` |
| `T.handoff → T` | 承接自哪一格 |

### 7. 工具（單一 CLI，Python 標準函式庫）

寫入指令：

| 指令 | 作用 |
|---|---|
| `new <slug> --topic <文字>` | 建立 thread 檔與時間戳 |
| `add <thread> <q\|d\|o\|t> --title … [--answers …] [--supersedes …] [--needs …] [--basis …]` | 新增條目，正文從 stdin 讀；編號與時間戳由 CLI 分配 |
| `set <addr> <state> [--source …]` | 轉移狀態，依第 5 節檢查權限 |
| `note <addr> <kind> <文字>` | 在 T 的沿革追加一行 |
| `rewrite <addr>` | 重寫 T 的正文（stdin）；不適用於 D、O |
| `append <addr>` | 在 Q 追加補充（stdin） |

讀取與檢查指令：

| 指令 | 對象 | 作用 |
|---|---|---|
| `queue` | 人 | 等你的事：open 的 Q、proposed 的 D、landed 的 T |
| `index` | 兩者 | 重新產生 `head.md` |
| `show <addr> [--history]` | agent | 單一實體、它的依據、thread 的「主題」、相關的 D（含是否已被取代） |
| `check` | 兩者 | 一致性檢查；也能當 post-edit hook 使用 |

檢查碼草案：

- **衝突**：`BAD_FORMAT`、`BAD_STATE`、`MISSING_SOURCE`、`DANGLING_REF`、`CYCLIC_NEEDS`、`DUPLICATE_THREAD`、`BASIS_SUPERSEDED`（T 的 basis 引用了已被取代的 D）、`NOT_CANONICAL`（檔案內容不等於 CLI 重新渲染的結果，即有人手改過）。
- **警告**：`OVERGROWN`、`HEADER_TOO_LONG`。
- 原草案的 `STAMP_OUT_OF_ORDER` 刪除：時間戳由 CLI 單調分配，手改則由 `NOT_CANONICAL` 抓。
