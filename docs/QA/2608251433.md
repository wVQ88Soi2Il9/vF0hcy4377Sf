## Questions and Answers

### Q1 · 2026-08-25 14:32 (human: wVQ88Soi2Il9)
Why did I originally mandate that all imports must go through `@/API`? Inter-pack dependencies shouldn't need that now, since each pack already has a unified export in its own `index.ts`.

### A1 · 2026-08-25 14:33 (agent: gemini-3.7-flash)
Correct. This reflects the evolution of module boundaries:

1. **`@/API` was originally a Core Engine facade**:
   - The initial intent was to create a one-way defensive boundary between the **Core layer (`src/core/`)** and **external packs (`src/packs/`)**.
   - It prevented Packs from directly coupling to internal Core details (internal maps, raw arrays, private helpers).
   - Core engine access went through `@/API`.

2. **Inter-pack dependencies are module-to-module**:
   - With the pack module object architecture, every Pack has a single public SSOT entrypoint at `src/packs/<pack_name>/index.ts`.
   - Each Pack exports its public types, utilities, and pack module from its `index.ts`.
   - **Inter-pack dependencies import directly from the target pack root (`import ... from '@/packs/<target_pack>'`)**, without going through `@/API`.

### Q2 · 2026-08-25 14:35 (human: wVQ88Soi2Il9)
Should I rename `API.ts` to `index.ts` and place it inside `core`, just like the other packs?

### A2 · 2026-08-25 14:37 (agent: gemini-3.7-flash)
Yes. This achieves complete symmetry and consistency across the repository:
- **Unified module structure**:
  - Core module: `src/core/index.ts` (imported as `@/core`).
  - Pack modules: `src/packs/<name>/index.ts` (imported as `@/packs/<name>`).
- Old rule: Everything must be imported from `@/API`.
- **New rule**: When crossing a module boundary, import strictly from the target module's `index.ts` public entrypoint; deep-importing internal files is forbidden.

## Conclusion

The module boundary conventions converge on the **Public Entrypoint Rule**:
1. **Core purity (zero global state, zero external dependencies)**: `src/core/index.ts` serves as a clean barrel export; runtime state and operations reside in `@/runtime` (later `@/world`).
2. **Utilities modularized into Packs**: Vector math, spatial hashing, coordinate validation, and namespace parsing live in packs (e.g., `@/packs/vanilla_beta` / `vanilla_alpha`) and export via public `index.ts`.
3. **Cross-module public entrypoints**: Any cross-module import must use the target module's public entrypoint `index.ts` (e.g., `import ... from '@/core'`, `import ... from '@/packs/<name>'`).
4. **No deep internal imports**: Cross-module imports into internal files (e.g., `from '@/core/commands'` or `from '@/packs/vanilla/overlap'`) are forbidden.
5. **Deprecation of `src/API.ts`**: The top-level `src/API.ts` facade is eliminated.
