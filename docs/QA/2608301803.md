# QA｜Hook 與 World / Operation 的關係

**Q：Hook 應該屬於每個 world instance 嗎？**

A：不需要。

Hook registry 接近靜態定義，保存某個 hook 對應的 callback sequence：

```ts
Map<hook_id, callback[]>
```

`Array` 是刻意的：callback 的順序與重複可能具有語義，因此應允許：

```text
func_a → func_b → func_a
```

下游若要求 callback 唯一，可自行增加限制，不應由 core definition 強制使用 `Set`。

---

**Q：多個 world 同時存在時，static hook 不會混淆嗎？**

A：不會。`world` 應作為 callback 的 argument 傳入，而不是成為 hook registry 的一部分。

概念上：

```ts
trigger_hook('device:moved', world_a);
```

等價於：

```ts
func_a(world_a);
func_b(world_a);
func_a(world_a);
```

因此 callback 操作的是此次 trigger 傳入的 world，不需要讓每個 world 各自持有一份 hooks。

---

**Q：誰應該 trigger hook？**

A：原則上，真正執行 state transition 的 operation 應負責 trigger 對應的 hook。

例如：

```text
move_device.execute(world)
    → 修改 world
    → trigger device:moved(world)
```

如此不論 operation 是由 UI、CLI、history 或其他入口執行，都能產生一致的事件。

History 若自身狀態發生變化，仍可另外 trigger history-specific hook：

```text
operation.inverse(world)
    → domain hook

history cursor changed
    → history hook
```

兩者描述不同層級的事件，並不衝突。

---

**Q：因此 reversible_operation 應操作 space 還是 world？**

A：若 operation 負責 trigger hook，應考慮操作 `world`。

原本：

```ts
execute(space): void;
inverse(space): void;
```

改為：

```ts
execute(world): void;
inverse(world): void;
```

因為 `world` 是完整的 runtime instance/context；operation 對該 world 執行 state transition，並將同一 world 傳給相關 hook callbacks。
