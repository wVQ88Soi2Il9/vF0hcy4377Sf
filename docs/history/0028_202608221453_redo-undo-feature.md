## 主題簡述

為系統設計並實作基於 Command Pattern 的樹狀歷史記錄與撤銷（Undo）/ 重做（Redo）機制（Undo Tree）。
支援裝置建立、刪除、移動、食譜配置等操作的分支歷史管理，杜絕線性歷史撤銷後誤操作導致 Redo 遺失之問題；並提供 API、CLI 指令與 UI 面板之快捷鍵與互動整合。

**本計畫的約束**

- 嚴格遵循 Allman 大括號風格、全小寫 snake_case 命名與結尾分號 `;`。
- 遵循三層單向架構，Core / API 保持單純，Pack 僅透過 `@/API` 與 Core 互動。
- 拒絕隱性補齊，狀態管理與向量運算嚴格匹配。

## 規劃描述

1. **Core 層型別與樹狀歷史容器（History Tree Manager）**：
   - 定義 `map_command` 介面（包含 `label`, `execute()`, `inverse()`）。
   - 定義 `history_node` 與 `history_tree` 結構（節點包含 `id`, `parent_id`, `children_ids`, `active_child_index`, `command`）。
   - 實作 `src/core/history_manager.ts`：包含 `push_command`, `undo`, `redo` 及基於 LCA（最近公共祖先）之任意節點 `jump_to_node` 遍歷切換演算法。
   - 擴充 `src/core/hooks.ts` 支援 `on_history_change` 事件派發。
   - `src/core/map_manager.ts` 擴充支援特定 UID 裝置還原（`restore_device`），確保重做時 UID 不跳號。
2. **Runtime 與 API 層封裝**：
   - `src/runtime.ts` 管理全域 `_history_tree`。
   - `src/API.ts` 暴露 `execute_command`, `undo`, `redo`, `jump_to_history`, `get_history_tree`, `on_history_change`。
   - 提供 4 大標準 Command 工廠（建立、刪除、移動、食譜選擇）。
3. **CLI 與 UI 整合**：
   - `src/packs/basic_ui/cli_executor.ts`：支援 `undo`, `redo`, `history`, `jump` 指令，並將既有 create/delete/move 改由 `execute_command` 驅動。
   - `src/packs/basic_ui/`：將 `device_creator.ts`、`device_card.ts` 異動改由 Command 驅動；全域掛載 `Ctrl+Z` / `Ctrl+Y`（`Ctrl+Shift+Z`）快捷鍵監聽。
4. **編譯與驗證**：
   - 執行 `npm run build` 確認 0 型別與建構錯誤。
   - 驗證線性 Undo/Redo、分支切換與 UID 一致性。

## 觀察與推論

### O1 · 2026-08-22 14:53:00+08:00 — 操作歷史與 Redo / Undo 機制需求
在畫布與面板進行裝置編輯時，需要可逆的操作歷史管理機制（Undo / Redo），以便使用者隨時撤銷或重做變更。

### O2 · 2026-08-22 15:00:00+08:00 — 樹狀歷史（Undo Tree）架構優勢
傳統線性 Stack 在撤銷後執行新操作會銷毀未來的 Redo 分支；採用樹狀歷史（Undo Tree）完整保留所有分支，配合 LCA（最近公共祖先）路徑計算，能以正反向 Command 達成任意歷史節點無損跳轉，且天然向下相容線性操作。

### O3 · 2026-08-22 15:20:00+08:00 — 專案現有架構對 Command Pattern 的天然契合性
地圖狀態異動 100% 收斂於 `map_manager.ts` 的 4 個純函式（`create_device`, `delete_device`, `move_device`, `select_recipe`），且由 Core Hooks 進行被動廣播重算（Renderer / Overlap / Graph 連動）。Command 封裝極度簡潔且零額外通知負擔。

### O4 · 2026-08-22 15:40:00+08:00 — UID 還原與狀態一致性
撤銷裝置建立後重做、或在不同歷史分支切換時，必須精確保留該裝置最初分配的 `uid`，`map_manager` 需支援指定 UID 復原或 Command 自行持有實例狀態，確保裝置參照與食譜設定在時空跳轉時保持絕對一致。

### O5 · 2026-08-22 19:03:22+08:00 — 歷史樹視覺化（History Visualizer）需求
目前 CLI 之 `history` 僅能文字列印節點列表，在 UI 上缺乏直觀的樹狀圖或分支結構呈現；需要設計並實作可視化繪製 History Tree（如樹狀圖、拓撲分支圖或歷史面板），並支援互動式節點選取與時空跳轉。
