## 確定的架構決策

### 1. Core Import 規則（放寬）

原規範「Pack 禁止直接 import `@/core/*`」過於嚴格。

**最終規則**：只禁止直接操作 `hooks` singleton（直接 push/splice）。
`@/core/types`、`@/core/pack_manager` 等模組可自由 import。

> 判斷原則：有沒有繞過訂閱機制？有 → 禁止。沒有 → 自由。

---

### 2. API.ts 的定位

**API.ts = 引擎公開事件契約**，由引擎開發者手動維護。

- 後續開發者打開 API.ts 就能看到引擎支援哪些事件
- 新增引擎能力時，手動在此加入對應的訂閱函式
- **不放**啟動期配管邏輯（set_map 等）

目前提供的訂閱入口：

| 函式 | 用途 |
|------|------|
| `on_device_create` | 裝置建立 |
| `on_device_delete` | 裝置刪除 |
| `on_device_move` | 裝置移動 |
| `on_device_change` | 任意生命週期變動 |
| `register_overlap_check` | 碰撞/越界驗證 |
| `register_graph_build` | 連接圖建構 |

---

### 3. runtime.ts 誕生

`set_map` / `get_map` / `set_registry` / `get_registry` 從 API.ts 移出，
獨立成 `src/runtime.ts`。

**職責**：啟動期狀態容器，不是事件 API。
- `main.ts` 在 `call_all_pack_inits()` 前寫入
- 需要地圖狀態的 pack（如 basic_renderer）在 `init_pack()` 內讀取

---

### 4. basic_renderer 改為標準 init_pack()

原本 `index.ts` 匯出 `init(canvas, map, registry)`，由 `main.ts` 手動呼叫。

**改後**：匯出標準 `init_pack(): void`，由 loader 自動觸發。
- renderer 自己建立 `<canvas>` 並掛進 `#app`
- 透過 `get_map()` / `get_registry()` 從 runtime.ts 取得狀態
- 加入 `window resize` 事件同步 canvas 尺寸
- 加入 `mouseleave` 防止拖曳狀態殘留
- 用 `queueMicrotask(draw)` 確保其他 pack 的 init_pack() 先跑完

---

### 5. register_device_draw 的歸宿

確定**不移入 API.ts**，終身住在 `@/packs/basic_renderer/draw_registry`。

其他 pack 要自訂繪製函式時：

```typescript
import { register_device_draw } from '@/packs/basic_renderer/draw_registry'
```

跨 pack import 的唯一允許例外。
