# 開發歷史紀錄 202608131703：Renderer 架構重構與強制裝置專屬 Draw Function

## 1. 背景與問題

原 Renderer 架構在 `draw_device.ts` 的 `draw_devices()` 函式內包含 inline fallback 繪圖邏輯（當 `get_device_draw(id)` 回傳 `undefined` 時，在內部繪製色塊或紅框）。

這違背了「每個 Device 強制要有自己的 draw function」原則，且使得繪圖的核心職責產生分歧與隱性補齊。

---

## 2. 彙總變更與完成事項 (Summary of Completed Tasks)

### Phase 1：重構 Draw Registry 繪圖註冊機制
- [x] **新增 `create_color_block_draw_fn()`**：在 `src/packs/basic_renderer/draw_registry.ts` 中提供建立純色塊 `draw_fn` 的工具函式。
- [x] **新增 `register_color_block_draw()`**：便利註冊函數，供 Pack 顯式為裝置藍圖註冊色塊繪圖邏輯。

### Phase 2：重構 Draw Device 繪圖核心
- [x] **純化 `draw_devices()`**：移除 `draw_device.ts` 中原本所有 inline fallback 色塊/紅框繪製程式碼。`draw_devices()` 現在無條件取得並呼叫 `draw_fn`。
- [x] **清理隱性補齊**：依據專案規範 Rule 4，移除 `visible_cells` 與座標比對中的 `?? 0` 隱式補齊邏輯。

### Phase 3：Basic Renderer 初始化時顯式註冊裝置繪圖
- [x] **顯式註冊裝置外觀**：在 `basic_renderer/index.ts` 的 `init_pack()` 階段，遍歷所有 `device_definitions`，為未自訂 draw function 的裝置定義顯式註冊對應的色塊 `draw_fn`。

### Phase 4：清理繪圖模組代碼風格
- [x] **修復 `draw_grid.ts` 與 `index.ts` 風格**：移除多餘的 `?? 0` 隱性補齊，確保符合 Allman 大括號與分號規範。

### Phase 5：提供 basic_renderer 物件導出 (Object Export)
- [x] **統一物件導出 API**：在 `basic_renderer/index.ts` 導出統一的 `basic_renderer` 物件，提供 `get_canvas`, `set_camera`, `register_draw` 等 API。
- [x] **重構對外調用點**：將 `basic_ui/index.ts` 與 `basic_ui/cmd_executor.ts` 的渲染器呼叫改為透過 `basic_renderer` 物件呼叫。
